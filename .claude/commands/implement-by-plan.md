# /implement-by-plan - 按 Plan 执行指定 Agent 任务

根据 Plan 文档中的 Agent 分配，执行指定编号的 Agent 任务。

---

## ⚠️ 核心原则（开始前必读）

**PRD 是唯一权威来源，必须严格按 PRD 功能完成实现。**

1. **功能完整性**：PRD 定义的每个功能点必须 100% 实现，不能遗漏、简化或"后续再做"
2. **测试全通过**：所有相关测试必须通过，**禁止跳过（Skip）任何测试**
3. **验收前检查**：勾选任务清单前，必须确认代码实现与 PRD 完全一致

---

## ⚠️ Agent 职责边界（必须遵守）

**本 Agent 只完成指定编号的任务，严格遵守以下规则：**

### ✅ 必须做

- 完成 Plan 中分配给本 Agent 的所有任务
- 为新增代码编写测试
- 通过测试（修复本 Agent 代码引入的测试错误）
- 通过 lint/TypeScript 检查（修复与本 Agent 相关的错误）
- 在 Plan 文件中勾选已完成的任务

### ❌ 禁止做

- 完成其他 Agent 的任务
- 修复其他 Agent 疑似导致的测试错误
- 修复与本 Agent 无关的 lint 错误
- 推荐"下一步应该执行 Agent X"
- 越界修改不在任务范围内的代码

**完成本 Agent 任务后直接结束，不要建议用户继续执行其他 Agent。**

---

## ⚠️ 实现与计划不一致处理（必须遵守）

**PRD 是权威来源，Plan 必须与 PRD 和实际实现保持一致。**

### 发现不一致时的处理流程

```
实现过程中发现 Plan 与 PRD 不一致
         │
         ▼
    ┌─────────────────────────────────────┐
    │  1. 立即暂停实现                      │
    │  2. 向用户报告差异                    │
    │  3. 等待用户确认处理方式               │
    │  4. 更新 Plan 使其与 PRD 一致          │
    │  5. 继续实现                         │
    └─────────────────────────────────────┘
```

### 不一致分类与处理

| 类型 | 示例 | 处理方式 |
|------|------|---------|
| **小偏差** | 命名、细节调整 | 按 PRD 实现，完成后更新 Plan |
| **代码位置变化** | 文件路径、行号、函数位置 | 实现后更新 Plan 中的位置信息 |
| **重大偏差** | 技术方案、架构变化 | **立即暂停**，向用户报告，等待确认 |
| **Plan 与 PRD 冲突** | Plan 写 v7，PRD 要求 v4 | **立即暂停**，向用户报告，按 PRD 实现，更新 Plan |

### 必须同步更新的内容

Plan 中以下信息必须与实际实现保持一致：

| 类别 | 示例 | 说明 |
|------|------|------|
| **文件路径** | `src/types/entity.ts` | 新建/移动/重命名文件后更新 |
| **代码位置** | `entity.ts:50-80` | 行号变化后更新 |
| **函数/类名** | `parseEntity()` | 重命名后更新 |
| **技术方案** | UUIDv4 vs UUIDv7 | 方案变更后更新 |
| **依赖关系** | 引用的模块/包 | 依赖变化后更新 |
| **验收标准** | 覆盖率 ≥80% | 标准调整后更新 |

### 报告格式

发现不一致时，必须向用户报告：

```markdown
## ⚠️ 发现 Plan 与 PRD 不一致

| 项目 | Plan 描述 | PRD 要求 | 建议处理 |
|------|----------|---------|---------|
| ID 格式 | UUIDv7 | UUIDv4 | 按 PRD 实现 v4，更新 Plan |
| 字段名 | `user_id` | `userId` | 按 PRD 实现，更新 Plan |

**请确认是否按上述方式处理？**
```

### 任务结束条件

**以下条件全部满足才能结束任务：**

- [ ] 代码实现完成，**严格遵循 PRD 功能定义**
- [ ] **Plan 与实现一致**（无过时内容）
- [ ] **Plan 与 PRD 一致**（无冲突）
- [ ] 验收标准全部可勾选（有证据支撑）
- [ ] 测试**全部通过**（**禁止 Skip，禁止忽略失败**）
- [ ] Lint/TypeScript 检查通过

**禁止在以下情况下结束任务：**
- Plan 与实现不一致
- PRD 功能未完整实现
- 存在被跳过（Skip）的测试
- 存在失败的测试


## 执行流程

### 1. 解析 Plan 获取任务

```
1. 读取 Plan 文件
2. 找到「Agent 拆分与执行策略」章节
3. 定位指定 Agent 编号的任务范围
4. 提取该 Agent 负责的所有 Task
```

### 2. 加载上下文

```
1. 读取 Plan 开头的「输入文档」章节
2. 加载「必须加载」中的所有文档
3. 按需加载「可选阅读」中的相关文档
```

### 3. 执行任务

按顺序执行 Agent 负责的每个 Task：

```
对于每个 Task:
  1. 阅读 Task 描述和 PRD 对应章节
  2. 实现代码修改
  3. 编写/更新测试
  4. 执行「验收标准验证协议」（见下方 3.1）
  5. 仅当所有验收标准逐条通过后，才能勾选 Task
```

#### 3.1 验收标准验证协议（必须遵守）

**每条验收标准必须有对应的验证动作和证据，否则禁止勾选。**

验收标准分为以下类型，每种类型有不同的验证方式：

| 验证类型 | 标记 | 验证动作 | 证据要求 |
|---------|------|---------|---------|
| `[test]` | 需要运行测试 | 运行对应测试命令 | 测试输出显示 pass |
| `[compile]` | 需要编译检查 | 运行 `bun run typecheck` | 编译无错误 |
| `[inspect]` | 需要人工/代码检查 | 阅读代码确认实现 | 说明具体检查了什么、在哪一行 |
| `[run]` | 需要运行验证 | 执行具体命令验证行为 | 命令输出符合预期 |

**验证流程（每条验收标准都必须执行）：**

```
对于每条验收标准:
  1. 识别验证类型（test/compile/inspect/run）
     - 如果 Plan 中已标注类型（如 [test]），按标注执行
     - 如果未标注，根据内容判断：
       · 包含"测试通过"、"单元测试" → [test]
       · 包含"编译通过"、"TypeScript" → [compile]
       · 包含"字段存在"、"已移除"、"返回正确" → [inspect] 或 [run]
  2. 执行验证动作
     - [test]: 运行测试，等待输出
     - [compile]: 运行类型检查，等待输出
     - [inspect]: 阅读代码，记录文件路径和行号
     - [run]: 执行命令，记录输出
  3. 记录验证证据（在勾选时附上）
  4. 仅当验证通过才勾选该条
```

**勾选格式（必须附带证据）：**

```markdown
- **验收标准**:
  - [x] CRUD 操作通过单元测试 → `bun test crud.test.ts` 全部 pass (12/12)
  - [x] TypeScript 编译通过 → `bun run typecheck` 无错误
  - [x] 字段 `uuid` 存在于类型定义中 → `types/base.ts:15` 已确认
  - [ ] 乐观锁冲突返回 C4A-DATA-003 → ❌ 测试失败，正在修复
```

> **关键规则**：
> - 没有运行过测试就不能勾选 `[test]` 类标准
> - 没有运行过 typecheck 就不能勾选 `[compile]` 类标准
> - `[inspect]` 类必须注明检查的文件和行号
> - 验证失败的标准保持 `[ ]`，继续修复直到通过
> - **禁止假设"应该能通过"就勾选——必须实际执行验证**

### 4. 质量检查

**在勾选任务前，必须完成以下检查：**

#### 4.1 测试检查

```bash
# 运行相关测试
bun run test

# 如果测试失败：
# - 本 Agent 代码导致 → 修复
# - 其他 Agent 代码导致 → 不修复，记录问题
```

#### 4.2 Lint/TypeScript 检查

```bash
# 运行类型检查
bun run typecheck

# 运行 lint
bun run lint

# 如果检查失败：
# - 本 Agent 修改的文件 → 修复
# - 其他文件 → 不修复，记录问题
```

### 5. 更新 Plan 文件

**只有当以下条件全部满足时，才能勾选任务：**

- [ ] 代码实现完成，**与 PRD 功能定义完全一致**
- [ ] 新增代码有测试覆盖
- [ ] 本 Agent 相关测试**全部通过**（**禁止 Skip**）
- [ ] 本 Agent 相关 lint/typecheck 通过
- [ ] 验收标准**每条都已执行验证并附带证据**

> **重要提醒**：
> - 测试被跳过（Skip）视为未通过，必须修复后才能勾选
> - 勾选前必须对照 PRD 逐条检查功能是否完整实现
> - 如发现 PRD 功能未实现，禁止勾选并继续补充实现
> - **验收标准的勾选必须附带验证证据**（测试输出/文件行号/命令结果）

**勾选格式（必须附带验证证据）**：

Task 完成时，必须同时勾选 **Task 级别** 和 **验收标准内的所有子项**。
每条验收标准后面必须用 `→` 附上验证证据：

```markdown
### Task 1.1: 移除废弃字段
- [x] **PRD 对应**: 1.1 字段变更
- ...
- **验收标准**:
  - [x] TypeScript 编译通过 → `bun run typecheck` 无错误
  - [x] 相关测试更新并通过 → `bun test types.test.ts` 8/8 pass
  - [x] 废弃字段 `kind` 已从类型定义中移除 → `types/base.ts` 已确认无 `kind` 字段
```

> **重要**：
> - 验收标准中的每个 `- [ ]` 都必须逐一确认并勾选为 `- [x]`
> - **每个 `- [x]` 后面必须有 `→` 加验证证据**，没有证据的勾选无效
> - 只勾选 Task 级别而不勾选验收标准子项，视为任务未完成
> - **禁止写 `→ 已确认` 这种空泛证据**，必须说明具体验证了什么

## 错误处理

### 遇到其他 Agent 的问题

如果发现问题是由其他 Agent 导致的：

```markdown
## 发现的问题（非本 Agent 职责）

| 问题 | 疑似来源 | 影响 |
|------|---------|------|
| `TypeError: xxx is undefined` | Agent 2 Task 2.3 | 阻塞 Task 3.1 |
| lint error in `storage.ts` | Agent 2 | 非阻塞 |
```

**不要尝试修复，记录后继续完成本 Agent 可完成的任务。**

### 遇到阻塞性依赖

如果前置 Agent 未完成导致无法执行：

```markdown
## 阻塞性依赖

本 Agent (Agent 3) 依赖 Agent 2，但以下前置任务未完成：
- Task 2.1: IStorageAdapter 接口未定义
- Task 2.3: SqliteAdapter 未实现

**建议**：先完成 Agent 2 的任务。
```

**停止执行，报告阻塞原因。**

## 使用方式

```bash
# 执行指定 Agent
/implement-by-plan --agent 1 --plan .tmp/0.3.1/plan.md

# 简写
/implement-by-plan 1 .tmp/0.3.1/plan.md
```

或在对话中：

```
请执行 Plan 中的 Agent 1 任务：
- Plan: .tmp/0.3.1/plan.md
- Agent: 1
```

## 示例

### 示例：执行 Agent 1

**输入**：
```
/implement-by-plan --agent 1 --plan .tmp/0.3.1/plan.md
```

**Agent 1 负责**（从 Plan 解析）：
```
Phase 1: Core 数据模型重构
- Task 1.1: 移除废弃字段
- Task 1.2: 引入 uuid 物理主键
- Task 1.3: 引入 root_id 字段
- Task 1.4: 引入 versions 数组字段
- Task 1.4a: 全局修复 entity.version 引用
- Task 1.4b: 工作区 version 注入逻辑
- Task 1.5: 删除 requirement_id 字段
- Task 1.6: ID 规范重构
- Task 1.7: 新增实体类型 feat/checklist/spec
- Task 1.8: 新增 component_id 字段
```

**执行过程**：
1. 加载 PRD、代码地图、架构文档
2. 依次实现 Task 1.1 ~ 1.8
3. 为每个 Task 编写测试
4. 运行测试和 lint 检查
5. 在 Plan 中勾选完成的任务
6. 输出执行报告
