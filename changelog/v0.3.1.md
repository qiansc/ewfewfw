# v0.3.1 (2026-02-06)

> **Breaking Change 版本**：数据模型重构 + Server 端 TS 化，需运行迁移脚本升级现有数据。

## Breaking Changes

- 移除 `project_id`、`project`、`from_project`、`to_project`、`proposal_id` 字段
- `uuid` 替代原有主键策略，物理主键改为 UUID v4
- 实体逻辑唯一性由 `(root_id, id, version)` 保证
- `versions` 为受控字段，不可通过 DSL 或普通 save 修改，需使用专用版本管理工具
- ID 规范重构：根实体采用 npm 包名格式（`@scope/name`），子实体使用短 ID + 父引用字段
- MCP Store/Query 工具参数变更（移除 `proposal_id` 过滤，新增 `uuid`/`root_id`/`versions` 参数）
- Server 模式废弃 Python 后端，改用 TS 实现

## Added

- 实体新增字段：物理主键 `uuid`、包边界 `root_id`、版本集合 `versions`、需求关联 `requirement_id`、父组件引用 `component_id`
- 新实体类型：`feat`（Feat Manifest）、`checklist`（Feat Checklist）、`spec`（Functional/Technical Spec）
- 版本管理 MCP 工具：`c4a_store_add_version` / `c4a_store_remove_version` / `c4a_store_publish_version`
- Copy-On-Write 分裂机制：`splitEntity` 支持同一 `(root_id, id)` 对应多条记录（版本集合不重叠）
- `0.0.0` 作为 latest 指针，publish 时自动转移
- CLI 版本管理命令：`c4a version switch/add/remove/list/publish`
- Server 模式 SyncWorker 后台进程：`sync_tasks` 任务表、重试机制（max_retries=3）、已完成任务自动清理（7 天保留）
- `c4a_store_sync_status` 同步状态查询 API
- Server Embedding 多 Provider 支持：OpenAI（`text-embedding-3-small`）、Ollama、Pseudo
- Milvus gRPC 在 Bun 环境的兼容性验证测试
- 数据迁移工具：SQLite `migrateLegacySchema`、Server `migrateLegacyEntities`
- 端到端集成测试（MCP Store/Query Server 模式全流程）与迁移回归测试
- `.dockerignore` 优化构建上下文
- `c4a-spec.schema.json` Schema 定义
- Core 工具：`uuid.ts`（UUID 生成/校验）、`version.ts`（版本注入/解析）

## Changed

- Storage 适配层接口全面对齐新数据模型（`adapterCrudTypes`/`adapterSyncTypes`/`adapterSearchTypes` 等）
- ServerAdapter 重构为直连 MongoDB/Neo4j/Milvus（拆分为 `server-adapter/mongo.ts`/`neo4j.ts`/`milvus.ts`/`embedding.ts`/`syncWorker.ts`）
- LiteAdapter 大规模文件拆分：`relations.ts` → `relationsGraph/Parse/Persist`、`dataOpsContext.ts` → `dataOpsFeat/FeatEntities/History/MainEntities/Types/Workflow`、`utilsValidate.ts` → `utilsValidateChanges/Checks/Scope`、新增 `version-operations.ts`
- SQLite 存储层重构：新增 `entity_versions` 关联表管理版本集合，`uuid` 为主键，新增索引
- MCP Store/Query 工具参数与过滤逻辑适配 `uuid`/`root_id`/`versions`
- CLI 初始化/同步/状态/校验流程适配 `root_id`（兼容旧配置读取）
- Milvus Content-Based Indexing 策略：向量索引不存储版本字段，查询走 Two-Stage Retrieval（向量检索 + 版本过滤）
- Neo4j 图模型改为 State Node 模式（每个版本独立节点），支持 `EVOLVES_TO` 演进关系
- 乐观锁并发控制：save 操作支持 `expected_updated_at` 冲突检测
- ID 校验规则支持 npm scoped 包名格式，序号递增规则扩展（`001→999→a001→...`）
- 文件名转义规则：ID 中的 `/` 转义为 `--`
- Server 模式 Docker Compose 替换 Python 存储服务为 TS 实现，更新 MCP 容器构建与健康检查
- 架构与使用文档更新（ARCHITECTURE.md / README.md / CONTRIBUTING.md）
- Skills 提示词适配新数据模型

## Removed

- `packages/storage-backend/` Python 后端整包删除（废弃，由 TS ServerAdapter 替代）
- `packages/mcp-extract/src/parsers/pythonParser.ts` Python 解析器移除
- `packages/storage/src/proposal-context.ts` 提案上下文移除
- 独立 `feats` 表删除（Feat/Checklist 统一作为 `entities` 表中的实体存储）
- Legacy 字段：`project_id`、`project`、`from_project`、`to_project`、`proposal_id`、`source_repo`、`repo_id`
- `.claude/commands/v3/implement.md` 旧命令文件
